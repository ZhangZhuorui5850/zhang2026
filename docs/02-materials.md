# 02 · 材料盘点与题面体裁分析

> 这份文档回答一个问题：**这套提示词里的"风格假设"是从多少份材料里推出来的？**
> 结论分三类标注：`[单样本]` 只有一份材料支持，可能是偶然；`[多样本]` 多份材料一致；`[推断]` 我自己加的工程判断，没有直接材料支持。

## 2. 三种体裁的结构对照（别混用）

| 维度 | 个人科研实训（#1） | 实训 LAB 量规（#2） | 黑客松（#3） |
|---|---|---|---|
| 时长 | 一天 8 小时，多题 | 4–8 小时，单任务 | 12 小时，团队 |
| 产出 | 代码 + 结果 json + README + train.log | 可重跑程序 + 指标 + 一页分析 | Demo + BP + 路演 |
| 评分主体 | 自动脚本 + 人工看交付物 | 六维量规（100 分） | 人气贴纸票 + 导师四维打分 |
| 分档 | 指标为主 | 建议 80/100 且无完整性问题 | 名次 → 100/90/85/80/70/60 |
| 关键红线 | 提交格式错 → 0 分 | 标签泄漏 / 测试调参伪装 / 虚构结果 → 不通过 | 未交完整 demo+BP → 不得分 |
| 能否套用 | — | **可以借鉴量规维度** | **不能**（团队+商业维度与个人实训无关） |

> 结论：`docs/00-playbook.md` 里的时间盒与题型映射来自 #1；`P13.5 量规自评` 的六维来自 #2；#3 只用来理解"校区重视可展示性"，不进提示词。

## 3. 从多份材料中稳定出现的题面写作规律

`[多样本]` 以下五条在 #1 和 #2 里都能看到，可以当成硬规律：

1. **先给背景与目标，再给数据接口**：题面默认你会先理解"这题为什么存在"，然后才告诉你数据怎么读。
2. **数据一律给现成的加载入口**（Dataset 类 / `load()` 函数 / csv+说明），不要求你自己找数据。→ 所以第一个动作永远是"把加载入口跑通"，不是读论文。
3. **模型侧给死路径与加载代码**（ckpt 路径 + 官方加载函数 + 建议池化方式）。→ 所以"能不能 load"是 30 秒内必须确认的事。
4. **设置要求是编号条目，且含禁止项**（禁止改词表 / 必须固定 seed / 二选一需说明）。→ 这些是评分点，不是建议。
5. **提交物逐字列出**，且要求"可重跑 / 可复现 / 有日志 / 有一页分析"。→ 交付物本身就是评分项，不止指标。

`[单样本]` 只有 #1 才有的：

6. 明确的考场路径约定（`/vepfs-readonly/` 只读素材、`/vepfs/` 个人可写目录）、`ssh dev` 上机方式、A100 80GB。**这是往届惯例，本届可能变，进场必须 `ls` 确认。**

`[推断]` 我自己加的、材料里没有明说的：

7. 多题时先做"能最快出分的那道"，而不是按题号顺序做。
8. 一页分析要写"失败与取舍"——材料只写"分析"，我判断这是评委区分度最高的地方。

## 4. ZGCA 自家的六维 100 分量规（来自 #2，4 套 LAB 反复出现）

这是**最有价值的一份发现**：LAB-01/02/03 的量规维度高度一致，只是分值微调。以 LAB-03 为例：

| 维度 | 分 | 细则（原文口径） |
|---|---:|---|
| 数据与协议 | 20 | 数据/许可/哈希 5；划分 ID 与规模 5；训练专用缩放 5；训练前控制项 5 |
| 基线与指标 | 20 | 正确形状和损失 5；多数类与混淆 5；训练循环 5；手算/自测 5 |
| 有理由的候选 | 20 | 条件证明 8；正确映射与缩放 6；唯一改动/反驳条件 6 |
| 受控比较 | 15 | 全部结果 5；配对差与验证选型 5；测试边界 5 |
| 可复现交付 | 15 | 完整代码/命令/环境 5；checkpoint 推断恢复 5；日志与文件关联 5 |
| 一页结论 | 10 | 三个样本的证据 4；局限 3；下一步及未完成项 3 |

LAB-02 的版本几乎同构（15/20/20/15/15/15）。

**三条共通红线**（原文明确写了"才通过"）：
- 标签泄漏
- 测试集调参伪装成验证集选型
- 虚构结果 / 只交作者输出

→ 这三条正好对应 `P13` 的第 9/10/17 项与 `P13.5` 的"完整性红线"。**指标高但踩红线，直接不通过。**
