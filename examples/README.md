# examples · 题型模板（风格参照，**不是真题**）

五个文件都是**虚构**的，用途只有一个：让你（和 agent）在看到真实题面时，**30 秒内认出它属于哪一类**，
从而直接跳到对应的做法、参数区间和坑清单。

| 文件 | 题型 | 识别特征 | 主指标常见形式 |
|---|---|---|---|
| [task-01-finetune.md](task-01-finetune.md) | 预训练模型微调 | 题面给 `checkpoint 路径` + `tokenizer / batch_converter` + "禁止改动词表" | Accuracy / F1 |
| [task-02-rag.md](task-02-rag.md) | 检索增强问答 | 题面给文档库 + 要求"答案必须基于文档" + 引用 | hit@k / 正确率 |
| [task-03-tabular.md](task-03-tabular.md) | 结构化数据建模 | 题面给 csv/parquet + 特征说明 + 交叉验证要求 | RMSE / AUC |
| [task-04-scratch.md](task-04-scratch.md) | 从零训练 / 复现 | 题面**不给**预训练权重 + 要求消融 | F1 / AUPRC |
| [task-05-controlled.md](task-05-controlled.md) | 受控比较 / 消融 | 题面给**固定划分与预算**、要求提前写定选型规则、明说没有提升也算通过 | 六维量规（不以指标为主） |

## 真题题面的六段式结构（这一届的实际风格）

真实题面基本是这六段，`P1.2 题面解剖` 就是按这个结构做的：

| # | 段落 | 里面有什么 | 映射到哪个产物 |
|---|---|---|---|
| 1 | 题目 | 一句话 | `00_task.md` 的 `objective` |
| 2 | 题目背景与目标 | 领域意义 + 输入输出形式 + 指标 | `objective` / `metric` |
| 3 | 数据集加载 | 现成的 Dataset 类、划分、只读路径 | `inputs` + `01_env.md` |
| 4 | 模型与特征提取 | ckpt 路径、加载代码、pooling 方式 | `20_candidates.md` 的改动清单 |
| 5 | 模型与微调设置要求 | 编号条目：禁止项、二选一、必须说明 | `constraints` + `30_spec.json` |
| 6 | 提交内容 + 评分 | 逐字文件名、格式、指标 | `outputs` + P13 的检查清单 |

**第 6 段是最容易丢分的地方**：文件名大小写、json 字段名、条数、顺序。`P1` 要求逐字抄，`P13` 要求脚本核。

## 怎么用这四个文件

1. **考前**：读一遍，建立"看到这类题面就知道要干嘛"的反射。
2. **考场**：在 `P1` 之后，让 agent 回答一句：`本题属于 examples 里的哪一类？据此选哪个 SAFE 方案？`
3. **不要**：把这四个文件里的任何数字、路径、指标当成真值——它们全是占位符。

```text
# 可以直接粘给 agent 的一句话
本题风格可参照仓库 examples/ 下最接近的那一个题型模板（判断属于哪一类并说明理由），
但具体题目、数据、指标一律以我给你的题面为准，不得套用模板里的任何数字与路径。
```
