# 题型二 · 检索增强问答（虚构示例，仅示意题面风格）

> ⚠️ 全部虚构。真实题目不同。`<>` 为占位符。

## 题目：基于 <私有文档库> 的问答系统

### 题目背景与目标

给定 <文档库路径>（约 <N> 篇、<M> MB，含 <格式>），构建一个能回答关于 <领域> 问题的问答系统。
要求答案**必须基于文档内容**，并在给定测试集上达到稳定的 <指标> 表现。
需同时给出**检索层**与**生成层**的评测结果。

### 数据加载

```python
from <module> import <LoaderClass>
docs = <LoaderClass>.load(<文档库路径>)        # 返回 [{"doc_id":..., "text":...}, ...]
qas  = <LoaderClass>.load_qa(<测试集路径>)     # 返回 [{"qid":..., "question":..., "answer":...}]
```

文档库**只读**。测试集不含答案的引用位置，需自行检索。

### 系统要求

1. **切块**：自行决定 chunk size 与 overlap，并在 README 说明理由（建议从 256/64 起步）。
2. **向量化**：使用环境内**已安装**的 embedding 模型（`python3 -c "import <pkg>"` 先确认），**不允许现场下载**。
3. **检索**：top-k 检索 + （可选）重排；必须处理"检索不到"的情况。
4. **生成**：输出必须带引用 `doc_id`；无依据时输出 `"未找到"`，**禁止编造**。
5. **可复现**：固定 seed，同一输入两次运行结果一致。

### 提交内容

| 文件 | 内容 |
|---|---|
| `test_result.json` | `[{"qid":..., "answer":..., "citations":[doc_id,...]}, ...]`，qid 与测试集一一对应 |
| `README.md` | 六段式，含切块/top-k/重排的具体参数 |
| `代码` | 能 `--mode smoke` 端到端跑通（3 条样本，60 秒内） |
| `train.log` | 索引构建与评测日志 |

### 评分

- 检索层：`hit@k`、`MRR`
- 生成层：答案正确率、引用命中率
- 人工项：无依据时是否正确拒答（**这一项经常是分水岭**）

---

## 这一题型该走哪条线

| 步骤 | 做法 |
|---|---|
| 情报 | 先确认**环境里有哪些 embedding / 向量库**，这决定整个方案；不能假设能联网装 |
| 方案 | SAFE = BM25/字面匹配 + 抽取式回答；SOTA = 向量检索 + 重排 + LLM 生成；GREEDY = query 改写 + 多路召回融合 |
| 执行 | 先做 10 篇文档的 mini 索引，端到端跑通再上全量 |
| 提分顺序 | 切块参数 → top-k → 重排 → query 改写 → 拒答策略 |

## 这类题的五个坑

1. **现场下载 embedding 模型**：无外网必挂。先用 `01_env.md` 白名单确认。
2. **索引时间**：全量索引可能比训练还久，先算 ETA 再动手。
3. **只报生成不报检索**：题目要两层，只给一层直接丢分。
4. **幻觉**：检索为空还硬编答案，人工项归零。
5. **qid 对不齐**：提交 json 必须按 qid 一一对应，不能只按顺序。
