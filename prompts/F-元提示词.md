# F · 元提示词（一键启动 / 原生 fan-out / 判分官模拟 / 人工兜底）

> 这是整套东西的"总开关"。前面 A–E 是零件，这里是把零件装成自动化流水线的图纸。
> 三种用法，按你现场的工具条件选一种：
> - **F1 一键总启动**：给 CLI Agent（Codex / DSH / Claude Code），它自己 fan-out 子 Agent 跑完全流程。← 首选
> - **F2 原生 fan-out 指令**：Agent 有 `subagent`/`workflow` 类工具时，追加这条让它真正并行。
> - **F3 判分官模拟**：开局先跑，反推评分点，决定时间怎么分配。← 强烈建议
> - **F4 人工兜底卡**：Agent 全线不可用时，你照着念。

---

## F1 · 一键总启动（Autonomous Research Mission）

**用途**：考试拿到题目的第一分钟，把这一段 + 题面路径一起发给 Agent。
**输出契约**：自动建 `runs/` 目录树，自动跑完 G0→G5，每个 gate 落盘并汇报。

```text
【科研实训 · 自主任务模式 MARS-8H】

你被授权在本机与远程服务器上自主执行完整科研流水线。目标：在 8 小时内产出满足题面要求、指标尽可能高的提交物。

## 输入
- 题面：<题面文件路径，或把题面原文粘在下面>
- 数据根目录：<路径；未给则自行在 /vepfs-readonly、/vepfs、~/、/data 下探测并报告>
- 提交目录：<路径；未给则用 <数据根目录同级>/submission 并报告>
- 时间预算：<480> 分钟，现在开始计时。

## 你要建立的工作台（第一步就做，一条命令）
mkdir -p runs/{10_cards,20_plan,50_logs,70_ckpt,90_submission}
并写出 runs/00_MISSION.md，内容包含：题面全文摘要、时间预算表、门控清单、降级阶梯、禁止事项。

## 执行架构（你不是一个 Agent，你是一个编排器）
你拥有以下 9 个角色。你对每个角色只传递「文件路径 + 一句话目标」，不让它们互相读上下文。

| 角色 | 何时用 | 输入 | 输出 | 并行度 |
|---|---|---|---|---|
| Scout-TASK/DATA/METHOD/METRIC/RISK | G1 | 00_MISSION.md | 10_cards/<VIEW>.md | 5 并行 |
| Synthesizer | G1 收口 | 全部卡片 | 10_brief.md | 1 |
| Architect | G2 | brief | 20_candidates.md（3 方案） | 1（内部三角色） |
| RedTeam | G2 | candidates | 25_decision.md | 3 并行评审 |
| SpecWriter | G2 收口 | decision | 30_spec.json + .md | 1 |
| Coder | G3 | spec | 代码 + smoke.log | 1 |
| Runner/Monitor | G3/G4 | spec | 50_logs/*.log + 40_progress.md | 循环 |
| Fixer | 出错时 | error.log | patch + 复现命令 | 1（配额 3） |
| Writer + QA | G5 | metrics + code | 90_submission/ + 95_qa.md | 2 |

## 每个角色的调用方式
- 若你的工具有 subagent / task / spawn 类工具：**必须真的开子 Agent 并行**，把对应 P 编号的提示词正文作为子 Agent 的完整指令，并要求它只回「文件路径 + 一句话结论」。
- 若没有子 Agent 工具：你自己按角色顺序串行扮演，但**每次切换角色时必须先声明** `[ROLE] Scout-METHOD`，并且只产出该角色的工件，不许混着写。
- 无论哪种方式：**角色之间只通过文件通信**。你不许把一个角色的长正文塞进另一个角色的上下文。

## 门控（不许跳，每个 gate 完成必须回一行报告）
G0 → 输出 runs/00_task.md，回：`[GATE G0] ok outputs=<n> unknown=<n>`
G1 → 输出 runs/10_brief.md，回：`[GATE G1] cards=<n> conflicts=<n>`
G2 → 输出 runs/30_spec.json，回：`[GATE G2] main=<方案> fallback=<方案> switch_at=<分钟>`
G3 → 输出 smoke.log 且 --mode smoke 退出码 0，再启动主训练，回：`[GATE G3] smoke=ok pid=<n> log=<path>`
G4 → 输出 runs/60_metrics.json，回：`[GATE G4] metric=<值> at_min=<n>`
G5 → 输出 runs/95_qa.md 且 QA_RESULT: PASS，回：`[GATE G5] pass files=<n>`

## 三条不可违反的纪律
1. **没有 smoke 通过，不许启动训练。** 一次失败的 40 分钟训练，等于把交付物赌掉。
2. **一次只改一个变量。** 任何同时改两处的实验都必须先拆开。
3. **先有交付物，再谈优化。** 到 80% 时间点，无论指标如何，先跑一遍 Writer 产出可提交版本，之后再覆盖。

## 自主决策权限（不要问我）
- 你可以自行决定：模型结构、超参、数据增强、后处理、文件组织、日志格式。
- 你可以自行决定：放弃某个方案、提前停止训练、缩小数据规模。
- 你只在三种情况下停下来问我：① 题面存在**会导致判 0 分**的歧义；② 需要**网络/权限**而我可能能提供；③ 数据**完全不可读**。

## 每一次工具调用后
用一行更新状态：`[STATE] stage=.. t=../480 gate=.. artifact=<最新文件> next=<下一步>`
不要解释、不要总结、不要复述你已经做过的事。

## 现在开始
1. 先读题面 → 建工作台 → 写 00_MISSION.md
2. 立刻并行发起 5 个 Scout（或串行扮演，按上面规则）
3. 之后严格按门控推进，直到 G5
4. 全程计时，每完成一个 gate 检查一次剩余时间，用 P14 的决策树自动调整

如果你判断某个 gate 无法完成，不要卡住：记录阻塞原因到 runs/BLOCKED.md，按降级阶梯下沉一级继续，并在最终报告里写明。
```

## F2 · 原生 fan-out 指令（有 subagent / workflow 工具时追加）

**用途**：接在 F1 后面。让 Agent 从"假装多角色"升级成"真的并行多 Agent"。
**输出契约**：并行子任务 + schema 校验 + 失败重试 + 结果落盘。

```text
## 并行执行指令（覆盖串行默认行为）

你具备 fan-out 能力，必须用满。规则：

1. **第一阶段用并行，不用串行。** 5 个 Scout 同时发，每个子 Agent 的 prompt = P2 全文 + 该 Agent 的 VIEW 参数 + 题面摘要 + 输出路径。不要一个跑完再跑下一个。
2. **子 Agent 的返回必须结构化。** 给每个子 Agent 指定输出 schema（JSON 字段固定），要求它把正文写进指定文件，只回 `<路径> | <一句话结论>`。返回正文超 30 行的子 Agent 视为失败，重发并附一句"只要结论，正文落盘"。
3. **第二阶段要交叉，不要汇总。** 拿到 5 张卡后，再发 3 个并行子 Agent，每个只负责质疑其中两个视角之间的矛盾，产出"矛盾裁决表"。这一步是信息增益最大的地方，不许省。
4. **执行阶段要竞速，不要排队。** baseline 与 SAFE 兜底两条线同时起（若显存不够则串行，但要在 30 秒内决定）。哪条先出分就用哪条做主线的证据。
5. **长任务不占子 Agent。** 训练一旦启动，子 Agent 立刻结束并返回 `pid + log 路径 + 预计完成时间`，后续由主控按 P8 轮询。**绝不允许多个子 Agent 挂着等一个训练跑完。**
6. **失败重试上限 2 次**，第 3 次失败就换实现路径，不许无限重试同一个 prompt。
7. **子 Agent 之间不许共享上下文**，只共享文件。防止上下文爆炸和结论互相污染。
8. 每次 fan-out 结束后，用一张表汇总：`子任务 | 状态 | 产物路径 | 一句话结论 | 是否被采纳`，写进 runs/40_progress.md。
```

## F3 · 判分官模拟器（开局先跑，5 分钟）

**用途**：读完题面立刻跑。**决定时间怎么分配**，避免在低权重环节死磕。
**输出契约**：`runs/05_rubric.md`。

```text
你是本次实训的「出题人与评分脚本作者」。你的任务不是帮我，是**站在判分侧把分扣光**。

基于题面（和你能看到的数据目录、提交要求），产出评分模型：

1. 打分项拆解（10 项以内），每项给：权重估计、判定方式（自动脚本/人工看/两者）、得分梯度（0 分长什么样、满分长什么样）。
   必须覆盖：指标分、交付物完整性、可复现性、代码质量、README 质量、日志、方法创新性、时间效率。

2. 三个「致命失分项」：只要发生就直接接近 0 分的错误。按发生概率排序，每条给一条预防命令。

3. 三个「高性价比得分点」：投入 ≤20 分钟、能明显提分或明显加分的东西。

4. 一条「如果你只有 90 分钟，应该做什么」的最短路径。

5. 明确写出：有哪些东西看起来很重要，实际上评分根本不看（避免我浪费时间）。

输出到 runs/05_rubric.md，最后一行：
PRIORITY: <按权重排序的前 3 项，逗号分隔>

禁止客套。禁止写"通常评分会综合考虑"。全部给具体判断。
```

## F4 · 人工兜底卡（Agent 全线不可用时）

**用途**：模型不通、网络全断、工具调不动。**手抄照做也能拿到及格线以上的分。**
**预算**：全程。

```text
【科研实训 · 无 Agent 人工流程卡】

00:00–00:20 环境
  ssh 上机 → whoami / nvidia-smi / python3 -V / df -h ~ / ls 数据目录
  建目录：mkdir -p ~/work/runs/{50_logs,70_ckpt,90_submission}
  开 tmux：tmux new -s work

00:20–00:40 题面
  逐字抄下提交物清单与指标定义（写到 ~/work/NOTES.md）
  读 3 个样本，写下字段与标签分布
  找官方评测脚本：find / -name "*eval*" -path "*题目路径*" 2>/dev/null

00:40–01:10 最短基线
  用最笨的方法先出分：分类→逻辑回归/TF-IDF；回归→均值/中位数；检测→现成权重直接推理
  一行命令跑通评测，把分数记下来。这一步的价值 > 后面所有优化。

01:10–04:30 迭代（每次只改一处，改完立刻评测并记表）
  记录表：| 时间 | 改动 | 分数 | 是否保留 |

04:30–06:00 提分
  先看错误样本（10 个），再改；优先做不需要重训的（阈值、TTA、后处理、集成）

06:00–07:00 交付
  按题面逐字生成文件；README 六段；清洗 train.log

07:00–07:30 自查
  20 项 checklist，json 必须能 load，文件数必须对，数字必须与日志一致

07:30–08:00 冻结
  只读检查。打包备份：tar czf submission_backup.tgz 提交目录
```
