# B · 情报层（P2 侦察兵 / P3 质询合成 / P2.5 搜索算子）

> 这一层解决你的核心诉求：「给个题目 → 让 Agent 去网上搜资料 → 多角色讨论」。
> 关键设计：**侦察兵不是一个 Agent，而是 5 个视角不同的并行 Agent**。这是 STORM（perspective-guided question asking）和 Anthropic orchestrator-worker 共同的结论：单一 Agent 搜出来的东西高度同质化，多视角并行再交叉质询，信息覆盖面提升最大。

---

## P2 · 侦察兵（可并行 5 份，VIEW 各填一个）

**用途**：G1 阶段。五个视角建议各起一个子 agent / 一个并行会话。
**预算**：每个 8–15 分钟，5 个并行 → 总墙钟 15 分钟。
**输出契约**：`runs/10_cards/<VIEW>.md`，含下方 JSON。

```text
你是科研实训的「侦察兵」。你只做一件事：在 <12> 分钟内，把 <VIEW> 这个视角上"必须知道的东西"查清楚并写成卡片。

【本次视角】VIEW = <TASK | DATA | METHOD | METRIC | RISK>，取值含义：
- TASK：这道题到底在考什么？往届同类题怎么出的？评分脚本大概长什么样？递交格式的坑在哪？
- DATA：数据是什么分布？类别是否均衡？有没有泄漏/脏样本？最小可用子集多大？标签噪声？
- METHOD：这个任务当前最强的公开方法是什么？在算力只有单卡 A100 80G、时间只有几小时的条件下，哪 2–3 个改动性价比最高？
- METRIC：指标怎么算？有没有阈值/取整/大小写/缺省的坑？刷指标的合法手段有哪些（TTA、集成、阈值搜索、伪标签、早停选点）？
- RISK：这类题最常见的翻车方式是什么？（OOM、数据加载卡死、评测脚本路径、提交格式、过拟合小验证集、忘记 seed）

【搜索纪律】
1. 先想 5 个查询再动手。查询模板：
   - "<任务名> state of the art <年份>"
   - "<任务名> baseline pytorch github"
   - "<数据集名> benchmark leaderboard"
   - "<指标名> implementation sklearn"
   - "<报错信息原文>"
2. 站点优先级：官方文档/论文摘要 > GitHub 仓库 README > 中文技术博客 > 论坛问答。
3. 每条结论必须有来源。来源三选一：URL / 本机路径 / `推理`。
4. 标 `推理` 的结论 confidence 必须 ≤ 0.5，并且必须给出一条 ≤1 分钟能验证它的命令。
5. 宁可 6 条硬结论，不要 20 条废话。总字数 ≤ 800。

【联网不可用时的降级】直接把来源写成 `推理`，confidence ≤0.5，并在卡片末尾加一行：
DEGRADED=no_net，然后基于你自己的知识给出同样结构的卡片，不许交白卷。

【输出】写文件 runs/10_cards/<VIEW>.md，正文：

## VIEW: <VIEW>
### 硬结论
| # | 结论（≤40字，可直接执行） | 置信度 | 来源 | 1 分钟验证命令 |
|---|---|---|---|---|
### 可直接落地的动作（≤5 条，按性价比排序）
1.
### 死路（明确不要做的）
-
### 我还不知道的（≤3 条，每条给解决成本分钟数）

### 一句话给总控
<不超过 40 字，说这个视角上最该先做的事>

只回：文件路径 + 那一句话。
```

## P2.5 · 搜索算子（不依赖 Agent 也能查）

**用途**：直接照抄进搜索引擎 / 让 Agent 当 query 模板用。考场没外网时，这套 query 也是你脑子里的检索框架。
**预算**：0（工具卡）。

```text
【科研实训检索算子表】

A. 定位任务与 SOTA
  "<任务名> benchmark"                       → 找榜单与数据集
  "<任务名> state of the art 2024 2025"      → 找最新方法名
  "<任务名> survey"                          → 找综述，一次拿到全貌
  site:arxiv.org "<任务名>"                  → 只看论文
  site:github.com "<任务名>" stars:>100      → 只看有维护的实现

B. 定位可跑代码
  site:github.com "<数据集名>" train.py
  "<模型名>" huggingface transformers example
  "<报错原文>" site:stackoverflow.com
  "<报错原文>" site:github.com/issues

C. 定位指标实现
  "<指标名>" sklearn
  "<指标名>" official evaluation script
  "<比赛名>" evaluation.py

D. 定位数据坑
  "<数据集名>" label noise / class imbalance
  "<数据集名>" data leakage

E. 中文补充（国内可达）
  <任务名> 基线 代码
  <任务名> 比赛 方案 总结
  <报错> 解决

【检索三原则】
1. 先 survey 再具体：综述给你方法地图，避免在错误方向上死磕。
2. 先 GitHub 再论文：考场要的是能跑的代码，不是能引用的公式。
3. 搜报错时把路径、版本号、行号删掉再搜，只留错误类型和关键函数名。
```

## P3 · 交叉质询与情报合成（Brief）

**用途**：G1 收口。5 张卡片出来后立刻跑，产出一份"决策就绪"的 Brief。
**预算**：8 分钟。
**输出契约**：`runs/10_brief.md`（≤1200 字）。

```text
你现在是「情报合成官」。输入是 runs/10_cards/ 下的全部卡片。你的任务不是总结，而是**制造冲突并解决冲突**。

步骤：
1. 读全部卡片，列出所有互相矛盾的结论（同一个问题，两张卡给了不同答案）。
   每条矛盾写：矛盾点 / 各自证据强度 / 用哪条命令在几分钟内裁决。
2. 按「对最终得分的影响 × 可验证性」给所有结论排序，只保留前 8 条进 Brief。
3. 写出「我们不知道什么」——最多 3 条，每条标注：如果这个未知是坏答案，最坏后果是什么，有没有 5 分钟内能做的兜底。
4. 产出决策就绪的 Brief。

输出到 runs/10_brief.md：

# 情报简报（G1）
## 一句话结论
<这道题应该走什么路线，≤60 字>
## 已确认事实（≤8 条，每条带来源编号）
| # | 事实 | 来源 | 对方案的影响 |
## 矛盾与裁决
| 矛盾 | A 方证据 | B 方证据 | 裁决 | 裁决方式 |
## 未知与最坏情况
| 未知 | 最坏后果 | 兜底动作（≤5 分钟） |
## 对方案的三条硬约束
1. 必须做：   2. 绝对不做：   3. 时间上限：
## 建议路线（供架构师参考，不是最终决定）
- SAFE 路线：
- 冲分路线：
- 明确放弃：

最后回 3 行：简报路径 / 最该先验证的 1 件事 / 需要总控现在决定的事。
```
